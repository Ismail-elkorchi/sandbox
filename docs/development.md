# Development and qualification

Use Node.js 24 or newer and the repository's pinned Rust-compatible dependency graph.

```sh
npm ci
npm run check
npm test
npm run verify:native
npm run test:package
npm run test:scripts
npm run audit:licenses
npm run audit:unsafe
```

`npm run test:package` installs the packed unscoped `sandsurf` package and verifies its public declarations and platform artifact selection. Source CI compiles the Linux, macOS and Windows adapters independently of hardware-dependent image builds. Package CI validates the committed current-format x64 image; ARM package validation and the five-platform release pipeline require a newly built ARM image on a native KVM host. Hosted image-build runners currently lack KVM, so that pipeline is blocked, not qualified or replaced by software emulation. A successful compile or prerequisite probe does not qualify a VM engine.

Source transport tests assemble and verify the binary built on that runner, rather than using a committed binary from another build. Native assembly is independent of default OS availability: an absent architecture reports `defaultImageDigest: null`; a declared image must verify. Release gates still require both image architectures. The SDK entry point exports the current implementations directly from machine, execution, filesystem, image, network/resource, secret and artifact modules. Internal transport symbols and response decoders are not public package entry points.

macOS LaunchAgent definitions register startup-only commands. The launcher succeeds only after its original broker-owned worker acquires the private service endpoint; resource admission alone is not service readiness. The bounded native broker owns the durable API or supervisor, not the launcher or SDK connection. The registrations do not restart a completed launcher, and removing them does not stop the workers. Use explicit service-stop commands; automatic service-crash restart and GUI-domain logout survival are not promised.

Archive creation streams npm's package selection directly to disk; it does not buffer complete machine images or the compressed tarball in Node memory. Distribution bundles contain gzip disk blobs, not multi-gigabyte mostly-empty raw disks inside npm's tar stream. Native imports decode those blobs in bounded chunks into a private host-owned staging directory, verify the original manifest and every decoded artifact digest, then atomically publish the VM-native image. The immutable manifest identifies the computer independently of this transport. Raw disks are the sole internal materialized representation. Package lifecycle hooks are prohibited: build and verify the image/native artifacts explicitly before packing.

Linux egress uses a root-owned restrictive socket factory plus the kernel's local-delivery filter. Before authorizing egress, the operator installs the digest-verified native host as `/usr/local/libexec/sandsurf/sandsurf-host`, `network-boundary.nft` beside it, and the bundled `sandsurf-network.service` in `/etc/systemd/system/`, all root-owned and not group/world-writable. Enable that system service explicitly; SDK/service startup never changes host firewall policy. The dedicated `inet sandsurf_boundary` table is reserved for this mechanism. Its atomic installation does not flush other tables. The factory has no destination/grant API: it transfers fixed-mark TCP/UDP sockets and, for bounded control-plane observations, a read-only handle to its running executable plus the identity of its freshly verified kernel rule. Egress prerequisites and qualification bind those original bytes rather than a mutable installation pathname; peer pidfd support is required. Missing installation fails egress admission closed; normal inbound listeners and a default-deny machine do not require it. Root network administrators are trusted to preserve this rule and packet marks; qualification must exercise the installed host's routing/firewall configuration. The service has a separate 25% CPU, 64MiB memory and 40-task envelope, not an unbounded privileged helper. The INPUT boundary survives factory restart and retains restrictions on transferred sockets. CI tests address changes, executable replacement, and transferred-handle lifetime in a fresh root network namespace without modifying host interfaces or policy; this is mechanism validation, not VM qualification.

The deterministic parser smoke harness is `npm run fuzz:smoke`. The trust-boundary libFuzzer set is:

```sh
for target in sandsurf_protocol canonical_digest network_rules network_packet image_manifest image_archive guest_protocol firecracker_api; do
  cargo +nightly fuzz run "$target" -- -max_total_time=30 -max_len=1048576
done
```

Build a local guest image on native Linux with writable KVM, libguestfs (`guestfish`), and native QEMU. Package resolution, lifecycle scripts and filesystem manipulation run inside the hardware-isolated appliance. Its host kernel must be readable by the build account. Filesystem construction uses a fixed journaled, online-growable ext4 profile. The guest grows its own filesystem; the host never repairs or resizes a guest-controlled filesystem.

```sh
SANDSURF_LOCAL_IMAGE=1 \
SANDSURF_IMAGE_OUTPUT_DIRECTORY=/absolute/output \
npm run build:guest-image
```

Archive and offline disk-protocol tests run without virtualization. The image-build workflow checks the shared bounded parser and actual extractor metadata behavior; those are not VM qualification. Installed computer tests verify journaled roots and independent fork identities. Runtime offline execution uses the compiled-manifest-pinned Sandsurf boot image, Firecracker on Linux and HVF/WHPX QEMU on macOS/Windows, without a NIC or target-controlled boot. Bootstrap production alone requires libguestfs.

Release images require the private signing seed through `SANDSURF_IMAGE_SIGNING_KEY_FILE`; the seed must never enter the repository or logs. `npm run build:native` verifies the pinned Firecracker archive while staging the complete Linux payload. macOS and Windows builds compile pinned QEMU with HVF/WHPX only and bind its executable, firmware and relocated loader closure to one runtime manifest. Corresponding source includes the QEMU/firmware archive and hooks, plus each bundled library's exact installed Homebrew formula or signed MSYS2 source package. `qemu-dependencies.json` binds installed and relocated/signed library identities to shipped source/recipe bytes; release assembly, package tests and supply-chain generation reject incomplete inventories. Entry sources live under `vmm/qemu`, separate from generated `native` output. Both local builds and release assembly publish complete manifest-verified trees; failed staging preserves published artifacts. Downloads never occur during npm installation or workload execution.

On a qualified Linux x64 host, `SANDSURF_KVM_TEST=1 npm run test:package` runs the persistent-computer suite using the installed tarball's SDK, native binary and image. Build serially on memory-constrained hosts; do not compile while VM qualification is running.

Real VM qualification is separate. `npm run qualify:linux -- /absolute/new-report.json` first records native containment/NIC eligibility. A denied TAP setup exits 2 with a blocked report, without changing AppArmor, capabilities or host networking. Only an eligible host proceeds to the real installed-computer suite. Successful assertions retain check observations tied to the installed binary and exact native configuration. The runner writes actual scoped evidence and candidate runs beside the immutable prerequisite report, plus a separate result reporting failed, incomplete, or tested-unaccepted. Partial scopes cannot qualify and observations from different configurations cannot be combined. `sandsurf qualification-requirements --directory <root>` lists the authoritative scope requirements; `qualification-accept --directory <root> --run <run.json> --evidence <evidence.json> --operator <identity>` separately verifies and retains evidence with explicit operator attestation. Tests never perform acceptance. The independent source-quality and installed-package jobs do not treat a blocked hardware run as a pass.

Linux image imports use one independently supervised worker pool per host directory (1 CPU, 1 GiB RAM, no swap, 64 host tasks, 300-second runtime). The API and artifact workers have a separate 1-CPU, 512-MiB, 256-task pool; supervision has a separate 1-CPU, 128-MiB, 64-task pool. These budgets are reserved before VM admission, and kernel controllers are verified before serving. The API admits immutable jobs and commits results; the image worker cannot mutate the catalog. Result bytes survive API restart. A busy or interrupted pool retains the admitted operation rather than silently launching additional workers. macOS and Windows image controllers use the independent supervisor and a 25%-CPU, 256-MiB native envelope, with the original pool lease acquired before launch and transferred into the worker. This leaves the rest of the reserved image envelope for the isolated VM. Bytewise native imports need no filesystem executor. Disk recipes use one NIC-less hardware VM inside the remaining reserved envelope (512MiB guest RAM, with bounded native overhead). The actual VMM inherits original pool, operation, disk and immutable-input custody; selected bytes cannot publish before native termination. A removed management connection does not release custody. Worker-pool capability does not claim recipe or machine-boot qualification. Jobs and materializers share one verified, atomically published terminal result; there is no second worker completion record. Aggregate physical-storage quota is not implied by process limits or capacity reservations.

Persistent machine/image storage rejects Linux tmpfs and ramfs rather than charging VM disks as anonymous host memory. Machine creation and native image imports additionally require dedicated bounded ext4 block volumes. Mount roots, device identities, aliasing, descendant mounts and block capacities are verified; ordinary directories, bind aliases and RAM filesystems are not physical caps. Machine snapshots and output remain on the owning machine volume, including after destruction. Offline native scratch stays beside the owned disk; the reviewed immutable runtime cache occupies the bounded shared host volume. Bootstrap-only libguestfs scratch/cache likewise stays beside its owned build disk. Sandsurf does not mount, resize or recycle operator volumes.

For positive installed-image tests, set `SANDSURF_PACKAGE_TEST_DIRECTORY` to an operator-provisioned private host volume. Without it, installed-package tests verify explicit unsupported storage, binary transport and declarations without claiming image-import qualification. VM qualification requires `SANDSURF_QUALIFICATION_ROOT`, whose fixture layout and identities are included in the prerequisite report. Each fixture needs an independent shared host volume of at least 32GiB; `computer` also needs a 40GiB machine volume for `CON`: it retains multiple complete disk/RAM captures and their interrupted-publication reservations. Every other machine identity needs an independent 8GiB volume at its `storage-path`. Forks declare their own envelopes rather than copying the capture-test reservation. Qualification keeps retained evidence; cleanup/unmount/recycling is an explicit later operator action. Missing storage or native NIC prerequisites exits 2 before VM tests. Neither hosted CI success nor a blocked local run qualifies these mechanisms.

Platform qualification requirements:

- Linux requires writable KVM, the source-built guest image, containment checks, interrupted-operation recovery, installed-package validation, and the KVM environment suite.
- macOS requires a real Mac with usable HVF, the installed resource broker and complete entitled QEMU runtime, guest boot/control tests, owner-death containment, and installed-package validation. The empty HVF probe and native compile are not VM qualification.
- Windows requires usable WHPX, independent installed service owners outside ambient Jobs, the complete QEMU runtime, Linux guest boot/control tests, original-process/Job containment and transferred disk-custody checks, interrupted recovery, and installed-package validation.

Qualification evidence is exact to the engine, architecture, boot bundle, native runtime closure, guest protocol, and tested host configuration. Unsupported mechanisms fail explicitly; there is no host-process or cloud fallback.
